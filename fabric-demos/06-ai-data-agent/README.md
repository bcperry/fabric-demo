## Evidence Review Journal

[review_workflow.py](review_workflow.py) stores requests and human decisions in
`EvidenceReviewJournal`, keyed to the immutable package identity. Its default is
validation only; `--execute` persists a record. A decision requires a rationale
and explicit `--human-reviewed-source-bytes` confirmation by the actual reviewer.
`ACCEPT_EVIDENCE` is package acceptance only, never finding closure or execution
authorization. The package remains an immutable snapshot; inspect the journal
for subsequent decisions.

```bash
env -u UV_DEFAULT_INDEX -u PIP_INDEX_URL uv run python fabric-demos/06-ai-data-agent/review_workflow.py REQUEST_REVIEW --rationale 'Ready for source inspection' --execute
```

The rehearsal persisted only `REQUEST_REVIEW`. This is a demo workflow, not a
certified approval system: application checks are not a substitute for separate
reviewer roles, server-enforced authorization, retention, or tamper-resistant audit.

## Linked Finding Closure

[finding_closure.py](finding_closure.py) creates a separate administrative
data-quality finding for the recorded streaming event, linked to the exact
hash-verified package, rejected event ID, and source line 15. It does not relabel
the independent Kadena fixture. Closure accepts retention of the quarantined
record; it does not claim repair, complete capture, test success, or authorization.

```bash
env -u UV_DEFAULT_INDEX -u PIP_INDEX_URL uv run --with 'psycopg[binary]>=3.2,<4' python fabric-demos/06-ai-data-agent/finding_closure.py REHEARSE --execute
env -u UV_DEFAULT_INDEX -u PIP_INDEX_URL uv run --with 'psycopg[binary]>=3.2,<4' python fabric-demos/06-ai-data-agent/finding_closure.py PROVISION --execute
```

`REHEARSE` exercises requested changes, evidence acceptance, closure, and audit
against PostgreSQL, then rolls back all test writes. `PROVISION` leaves the
finding open. Actual reviewer commands are `ACCEPT_EVIDENCE`, `REQUEST_CHANGES`,
and `CLOSE_FINDING`, each requiring `--rationale`,
`--human-reviewed-source-bytes`, and `--execute`. Without `--execute`, only local
evidence and arguments are checked; current database state is not checked.

Transitions lock the finding and disposition rows, validate event/package
identity and prior state, and write the administrative status and audit in one
transaction. The audit records the database session identity. This is separate
from the Eventhouse package-review journal: accepting a package there does not
implicitly approve this disposition. Database administrators can still alter
these demo tables; this is not an immutable or independently authorized audit.
